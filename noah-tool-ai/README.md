# Noah Tool AI

Noah Tool AI is a local chat interface for the providers in this repository's catalog, plus xAI (Grok). It routes prompts to available models, can compare two providers and synthesize their drafts, and keeps chat history and projects in the current browser. Kilo Code, LLM7.io, and OVHcloud AI Endpoints are preconfigured for their catalog-listed anonymous tiers, so you can start without entering API keys.

## Run locally

On Windows, double-click **Start Noah Tool AI.bat** in the repository folder. It checks for Node.js, starts the local server, and opens the app in your browser.

On Windows PowerShell, if you want to start it manually, use Node.js 20 or newer and run from the repository root with `npm.cmd` (PowerShell may block the `npm.ps1` script):

```powershell
npm.cmd start
```

Open `http://127.0.0.1:4173` and start chatting. In Auto mode, clear requests to make, build, create, or design a website open the website builder automatically; you can also select **Create a website** explicitly. Review the private preview, then choose **Publish public website** and confirm to receive a public link. To publish, install GitHub CLI, double-click **Connect Noah Tool AI to GitHub.bat**, and complete the one-time GitHub sign-in. Each publish creates a new public repository containing only the reviewed website HTML and enables GitHub Pages for it.

Auto routing analyzes the latest request with a lightweight internal task classifier, then scores configured provider models using their catalog names and modality (for example code, reasoning, and vision indicators). This is routing logic and prompt guidance, not a separate hidden LLM or an installed design engine; selecting a model manually still pins the first draft to that model. For substantial creation, analysis, recommendations, and other multi-step tasks, a different provider reviews and revises the answer when available. Simple factual questions skip the extra review call. The reviewer checks prompt fit, accuracy, completeness, and relevant missing detail; it should expand useful gaps without padding or overriding scope. If review is unavailable, the first draft is kept and the app says so. Extra model calls can use more quota. Website generation also uses a dedicated visual-design brief and second-model critique for composition, hierarchy, typography, responsive behavior, accessibility, and working interactions. The app does not execute generated code or guarantee that it works; test it in its target environment.

The chat composer accepts up to five photos, videos, audio clips, and text/code files per message. Images are resized in your browser and sent to a configured vision-capable provider; videos are represented by up to four sampled frames; MP3/WAV audio is sent to a provider with audio-input support (16 MB maximum). Text/code files (up to 500 KB each) are included as prompt context. Supported text formats include TXT, Markdown, CSV, JSON, HTML, CSS, JavaScript/TypeScript, Python, and common source/config formats. PDFs and office documents are not parsed. Attachments are sent to the model provider with your request and their file contents are not saved into chat history by the app; attachment names are saved with the message. Provider privacy and retention rules still apply. Image/video analysis requires an available vision model, audio requires an audio-input model, and video decoding depends on your browser's supported formats.

Use **Host a website on Vercel** to connect a Vercel access token and deploy either the reviewed generated HTML site or a local project folder. Vercel auto-detects common frameworks, including Next.js, Vite, and Create React App. Give the project a name for its `*.vercel.app` production URL, and optionally attach a custom domain that you own; domain verification/DNS may be required. Noah stores the Vercel token locally in the gitignored credentials file and never returns it to the browser. Project uploads are limited to 150 files and 8 MB total (4 MB per file); `node_modules`, `.git`, `.next`, `.vercel`, and common credential files are excluded, and recognizable API tokens are rejected. The deployed site is publicly reachable; project source is sent to Vercel, where build scripts may execute, so inspect the project and remove secrets before confirming. Vercel controls plan limits, production availability, and domain requirements.

The chat assistant is instructed not to reject a topic just because it involves sex, and to help with sexual-health, relationship, consensual adult, and adult-oriented tool requests respectfully. Age, consent, and provider-level content rules still apply; app instructions cannot override a provider's moderation or guarantee every model will answer every request.

The response-mode menu also includes guidance inspired by **OpenDesign** for design systems and visual refinement, **ComfyUI** for modular image/video-generation workflows, **Dify** for AI app orchestration, **AI Investigator** for evidence-led research, **OpenCLI** for browser automation plans, **pytorch-grad-cam** for vision-model attribution, **Objectron** for 3D object-dataset and geometry workflows, and **Moorph GUI Clean** for AI-assisted browser CAD. These linked projects are not plug-in models: Noah does not install or invoke them, operate a browser, browse sources, deploy workflows, access Objectron data, run model explanations, edit CAD scenes, or generate media. Their modes guide the selected language model and provide setup/code plans; actual execution needs the relevant software, model, data, and local setup. Website creation additionally gets a dedicated second-model visual and functional review when another provider is available. Model review adds provider requests and can use more quota. Regular chat remains general-purpose for questions, coding, game scripts such as Roblox/Luau, and other tool-building tasks; use **Create a website** specifically when you want a ready-to-preview static website.

On macOS, Linux, or Windows Command Prompt, run `npm start`. For additional chat models, choose **Settings & providers** and optionally add one or more API keys per provider, one per line. Keys are provider-specific; an Aion Labs key does not authenticate with Grok or other services. An API gateway key works only with that gateway's endpoint and supported models.

Credentials are stored as plain text in the gitignored `noah-tool-ai/.local-credentials.json` file and are not returned to the browser after saving. Keep the app on your own computer; it binds to `127.0.0.1` and is not intended to be exposed to the internet. Chats and projects are stored in browser local storage.

The app rotates through configured keys after request failures, and Auto can fall back to other anonymous or configured providers. Anonymous tiers can impose strict rate limits, change without notice, or become unavailable; providers also have their own privacy terms. This app cannot guarantee unlimited use. API compatibility and model availability can change, so configure a provider-specific HTTPS base URL in Settings when its catalog default does not work.

GitHub Pages is for static websites. Published sites are public; do not include personal or confidential information, passwords, API keys, or other secrets. The site source is stored in the repository created in your GitHub account. GitHub Pages is not intended for e-commerce or paid SaaS services, and has bandwidth, size, and usage limits. Review the [GitHub Pages usage limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits) before publishing.
